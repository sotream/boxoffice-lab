# ADR index

Every architecture decision record in the repository, one row each. The files are the source; the one-line decisions below summarise them and do not replace them. Each service also states the rejected options in its ADR file.

Statuses are copied from the files. "Accepted" means the decision is implemented in this repository. [ADR 005](../services/payments/adr/005-claim-refund-before-issuing-it.md) changes an earlier decision (the order of the compensation steps of payments ADR 001 and 004); [ADR 006](../services/payments/adr/006-internal-authentication-and-server-side-price.md) tightens ADR 003 (a repeated key is "the same request" only for the same user, event and seats); [inventory ADR 002](../services/inventory/adr/002-signed-internal-requests.md) applies the request signature of payments to inventory.

| ID | Service | Title | Status | Decision |
|---|---|---|---|---|
| inventory 001 | inventory | [How to hold a seat without double booking](../services/inventory/adr/001-hold-strategy.md) | Accepted | One conditional `UPDATE ... WHERE free RETURNING` in a single statement (`atomic-update`); `for-update` with `ORDER BY seat_id` is kept for comparison. Not check-then-write, not Redis `SET NX`, not serializable. |
| inventory 002 | inventory | [Authenticate callers with signed requests, a key of its own](../services/inventory/adr/002-signed-internal-requests.md) | Accepted | Every inventory route except the probes needs `x-internal-auth` (HMAC over timestamp, method, path, body hash; 30 s skew) with `INVENTORY_INTERNAL_TOKEN`, a key separate from payments'; the gateway and payments sign. The hooks are shared with payments. Still one shared key per callee, replay inside 30 s possible, the cost of the extra HMAC on the hot path was not measured. Not mTLS, not network trust. |
| waiting-room 001 | waiting-room | [Redis sorted set for the queue, sequence as score](../services/waiting-room/adr/001-redis-sorted-set-queue.md) | Accepted | `ZADD NX` with an `INCR` sequence as score (idempotent join, no clock skew), `ZRANK` for position, `ZPOPMIN` to admit. Not Postgres, Kafka or SQS. |
| gateway 001 | gateway | [Token bucket in Redis for rate limiting](../services/gateway/adr/001-token-bucket-redis.md) | Accepted | One Lua script (read, refill, take, write) per decision, time from Redis `TIME`. Not fixed window, sliding log or leaky bucket. |
| gateway 002 | gateway | [Signed admission token instead of a Redis lookup](../services/gateway/adr/001-token-bucket-redis.md#adr-002-signed-admission-token-instead-of-a-redis-lookup) | Accepted | HMAC token `user.event.expiry.signature` issued by waiting-room and verified by the gateway with no Redis call; revocation before expiry is not possible. |
| payments 001 | payments | [Orchestrated saga with compensation, not two-phase commit](../services/payments/adr/001-saga-over-2pc.md) | Accepted | Charge first, then confirm seats, refund if the confirm says no; the service owns the state machine. Step order of the compensation amended by ADR 005. |
| payments 002 | payments | [Transactional outbox, not "write DB then publish"](../services/payments/adr/001-saga-over-2pc.md#adr-002-transactional-outbox-not-write-db-then-publish) | Accepted | The outbox row commits with the state change; a relay publishes it (at-least-once). CDC is named as the production upgrade. |
| payments 003 | payments | [Idempotency key is a unique column](../services/payments/adr/001-saga-over-2pc.md#adr-003-idempotency-key-is-a-unique-column) | Accepted | `INSERT ... ON CONFLICT DO NOTHING` on `idempotency_key`; the database arbitrates concurrent duplicates. Not a Redis lock. |
| payments 004 | payments | [Bounded steps, "unknown" is not "failed", sweeper](../services/payments/adr/001-saga-over-2pc.md#adr-004-bounded-steps-unknown-is-not-failed-sweeper-added-after-drill-4) | Accepted | 2 s timeout per outside step, answer 202 in-progress, never compensate on a timeout, idempotent inventory confirm, a sweeper resumes stuck sagas. |
| payments 005 | payments | [Claim the refund (REFUNDING) before issuing it](../services/payments/adr/005-claim-refund-before-issuing-it.md) | Accepted | `CHARGED -> REFUNDING` by compare-and-set before the keyed refund call, so only one runner can refund; `REFUNDING` is in progress, not final. Supersedes the compensation step order of ADR 001 and 004. |
| payments 006 | payments | [Internal authentication and server-side price](../services/payments/adr/006-internal-authentication-and-server-side-price.md) | Accepted | Payments is reachable only through the gateway route `POST /events/:id/pay`; every request carries `x-internal-token` (checked in an `onRequest` hook, constant time), the price is `seats x SEAT_PRICE_CENTS`, and a replayed idempotency key with another user, event or seats is a 409. Not mTLS, not a forwarded JWT, not network trust. Amends ADR 003. |
| payments 007 | payments | [Ask inventory who holds the seats before charging](../services/payments/adr/007-verify-holds-before-charging.md) | Accepted | A new payment is checked against inventory (read only) before the PSP is called; "not held" ends FAILED with no charge, "unknown" goes on and confirm decides; only on the first call, never when resuming a possibly charged saga |
| notifications 001 | notifications | [Kafka-compatible log (Redpanda) as the transport](../services/notifications/adr/001-kafka-for-notifications.md) | Accepted | A replayable log with a consumer group; retries, backoff and DLQ are application code. Not direct HTTP from payments, not SQS or RabbitMQ. |
| notifications 002 | notifications | [At-least-once with a database dedup key](../services/notifications/adr/001-kafka-for-notifications.md#adr-002-at-least-once-with-a-database-dedup-key) | Accepted | Send, then record; primary key `(outbox_id, channel)` plus a lease claim so two workers cannot send the same notification. |
| notifications 003 | notifications | [DLQ as a topic, and per-channel state](../services/notifications/adr/001-kafka-for-notifications.md#adr-003-dlq-as-a-topic-and-per-channel-state) | Accepted | Permanent failures (and malformed events) go to `<topic>.dlq` and the offset moves on; replay is safe because delivery state is per channel. |
| catalog 001 | catalog | [Postgres full-text search, not Elasticsearch/OpenSearch (yet)](../services/catalog/adr/001-postgres-fts-before-elasticsearch.md) | Accepted for this scale; revisit triggers listed in the file | `tsvector` column with a GIN index in the same database; Elasticsearch/OpenSearch was not run, only argued from documented trade-offs. |
| catalog 002 | catalog | [Cache-aside in Redis with single-flight and TTL jitter](../services/catalog/adr/001-postgres-fts-before-elasticsearch.md#adr-002-cache-aside-in-redis-with-single-flight-and-ttl-jitter) | Accepted | Cache-aside with per-process single-flight and TTL jitter of +-20%; staleness is a stated trade (at most 36 s for searches). |
